01 / THE SPARK

Start with a
reason to care.

I wanted a place to keep the things I learn: useful notes, honest experiments, AI tools, and the occasional life theory that sounds convincing after midnight.

The brief was simple: make it personal, make it useful, and make it sound like a human wrote it. Preferably this human.

A grand strategy? No.
A notebook with a URL? Exactly.

02 / THE FOUNDATION

Four pages.
Zero framework.

Each page is a regular HTML file. Shared navigation and footer make the site feel connected; plain links keep every page easy to open, edit, and understand.

No component library hiding behind the curtain. It’s all readable source files—like a recipe card, except the recipe has a footer.

The files are the architecture.

03 / THE SKELETON

HTML gives
ideas a shape.

Semantic elements make the page legible to people and browsers: a header, navigation, main content, sections, links, and a footer.

Then the content goes in. A headline, the archive’s notes, the tool cards. The most advanced part was deciding what to say. Naturally.

Readable markup is a gift
to future-you. Accept it.

04 / THE PERSONALITY

CSS makes it
feel like mine.

A little color palette, a few type styles, roomy spacing, and some abstract illustrations give the archive its own character. Soft paper colors meet forest green and a small hit of lime.

Responsive rules rearrange the layout for smaller screens. The design should be comfortable on a phone, not a desktop squeezed into a phone costume.

Good spacing: invisible.
Bad spacing: somehow the whole meeting.

05 / A LITTLE INTERACTION

JavaScript does
a few small jobs.

Vanilla JavaScript powers the mobile menu, remembers the light or dark theme, updates the year, and filters the tool directory.

And here, it turns the pages of this little book. Nothing needs a giant framework to open a menu. The menu is not running a space program.

Use just enough code
to make the useful thing happen.
script.js ● ● ●const menu = document.querySelector('.menu');

menu.addEventListener('click', () => {
  menu.classList.toggle('open');
});

// Look ma, no framework.

06
06 / TEST, THEN SHARE

Check the small
screens too.

I preview each page, follow every link, try the menu and theme switch, and check the layout at phone widths. The goal: no sideways scrolling and no mysterious disappearing buttons.

When the files are ready, a static host like Cloudflare Pages can publish them. Push an edit, let the host serve the updated site. Internet: a series of folders with excellent marketing.

Preview. Notice. Adjust.
Repeat until it feels right.

07
07 / THE LAST PAGE (FOR NOW)

Turns out, you
can just make it.

The big lesson: a website is not a mysterious object bestowed upon the chosen. It’s a set of files, some thoughtful choices, and a willingness to fix the bits that look odd.

Start small. Keep the code understandable. Make it yours. And maybe close a few tabs before starting another project.
